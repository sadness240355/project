## 修复内容

1. 保持原有顶层目录和既有设计文件位置不变。对修复前已存在的 81 个设计文件（RTL、C/C++、头文件、XCI、XPR、约束）逐字节核对，全部保持不变。
2. 从原 Vivado 工程补回 XPR 所需 RTL、IP、DDR 参数文件、约束及 HLS IP 封装。恢复缺失的板级入口/测试源码和信用通道对照输入，共补入 260 个文件；其中脚本随后按授权改为可迁移路径。详细来源见 `RESTORED_FILES.md`。
3. 补齐应用源码归档被截断的尾部：提交包原归档为 786432 字节，原件为 1290240 字节，原提交内容与原件前缀完全一致。修复后两个源码归档均通过逐成员完整读取检查。正式构建使用包内源码，不依赖解压归档。
4. 将已失效的 `source/`、`build/candidates/` 引用映射到现有 `src/` 分类；补回 `preflight.py`、`credit_board_idle.py`、RDMA 单轮和彩条构建/运行入口。
5. Vivado 根据原 XPR 文件清单创建干净工程，保留顶层、泛型、宏、include 目录、约束顺序、IP 仓库和时序钩子；不复用原工程运行状态、增量 DCP 和不存在的运行名。IP 导入构建目录，避免在源码目录生成输出。`create` 为默认阶段。
6. 修复 Tcl 文件列表的空格路径处理。Vitis HLS 2022.2 不接受带空格的 project/solution 路径，因此 C 仿真脚本在独立临时目录暂存输入，运行后回收证据并清理临时目录。
7. 软件构建只复制源文件，重新编译本机运行库和应用，不使用历史二进制；视频发送构建保留原最终脚本中的信用通道修正。Makefile 与 `video.sh` 的构建目标统一委托给随包脚本。
8. 板级设备、网络地址、运行库和应用构建名称可以通过环境变量选择。设备相关 C 字面量仅在构建副本中替换，记录 `host_config.json`。远程 SSH 入口不再绑定开发者主目录。

## 复现命令

在工程根目录依次运行：

```bash
bash build/reproduce.sh check
bash build/reproduce.sh sim run01_sim
bash build/reproduce.sh hls run01_hls
bash build/reproduce.sh software run01_sw
bash build/reproduce.sh vivado run01_fpga
```

最后一项仅创建 `build/run01_fpga/vivado/lrdma_repro.xpr` 和 IP 状态报告，不触发综合/实现。所有 ID 必须是新名称，只允许英文字母、数字、下划线和连字符。依赖和输出位置见根目录 README。

如评审后另行需要真正生成位流，`rebuild_clean.tcl` 保留显式 `synth` / `bitstream` 阶段，但本次未执行也未验收这些阶段。直接打开保留的原 XPR 可能看到已删除的旧增量检查点或原运行钩子提示；正式复现入口为新建工程脚本。

硬件实验参数和控制服务配置见 `board/README.md`。历史 `data/results/` 中按论文重建的记录保持原标记；本次离线检查不能替代硬件、时序或性能结论。
